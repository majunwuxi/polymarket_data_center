# NBA 交易记录器（开发中）

本项目正在验证 Polymarket 公开接口的采集方式，尚不能作为完整、准确的交易账本使用，也尚未部署为长期运行的服务。

当前代码只采集 NBA 全场胜负（Moneyline）、全场让分和全场总分的所有盘口；半场、球队总分、球员数据等其他市场不采集。每条盘口单独保存，不会把不同让分或总分线合并。旧数据库里以前保存的其他市场不会自动删除，但已停止采集，可在 `status` 看到提示。代码保存上述项目的接口原始交易记录、检查点和错误。默认查询主动方和另一方的记录；这两种记录不能直接相加当成市场成交总额。每条记录的身份仍然存在不确定性。

安装依赖：`python -m pip install -r requirements.txt`。

独立 Ubuntu VPS 的安装、后台运行、SSH 安全访问和备份方法见 [VPS 部署指南](docs/VPS部署指南.md)。

日历仪表盘：运行 `python dashboard.py`，然后在浏览器打开 `http://127.0.0.1:8068`。它只读取当前目录的数据库；使用其他数据库时运行 `python dashboard.py --db 数据库路径`。赛程由采集程序更新，页面本身不会启动采集。按 Ctrl+C 关闭仪表盘服务。

日历以中英文全名显示球队，点击任一队名在新页面打开对应的 Polymarket 比赛地址。尚未确认市场开放的比赛也提供候选链接，页面可能暂时不存在。项目面向独立服务器使用，不依赖 ChatGPT Sites；当前服务默认只监听本机，VPS 对外访问和安全配置需另行设置。

日历比赛卡片上的“查看比赛详情”进入单场盘口汇总页面，可筛选全场胜负、让分、总分，查看每个盘口各结果的买入金额、卖出金额、记录笔数和不同钱包数量。金额按价格乘份数估算，买卖双方记录不能直接相加当成网站成交额；未采集或清理后的比赛不会显示虚构数据。页面每分钟读取一次本地数据，但不会自行启动采集。

查看状态：`python recorder.py status`。实验性单轮采集：`python recorder.py once`。实验性持续采集：`python recorder.py run`。默认数据库为当前目录的 `nba_trades.sqlite3`，可用 `--db` 指定其他位置。按 Ctrl+C 停止。

默认三分钟开始下一轮，实际一轮耗时较长时会延后；每个市场从上次成功检查点向前重叠 15 分钟。每 24 小时尝试完整复查。检查成功不代表官方接口已返回所有数据。不要用现有数据直接计算主客胜投注排名。

程序每六小时尝试从 ESPN 的公开 NBA 赛程刷新未来比赛；按美国东部时间日期、客队和主队生成 Polymarket 候选地址。距预计开赛不超过八天时开始检查，查到对应事件后才加入采集。`status` 显示候选地址、开赛时间、待开放或已开放状态及错误。赛程改期时会更新地址并重新检查，已经保存的历史市场不会删除。若赛程来源无法访问，旧安排保留，错误显示在状态中；Polymarket NBA 标签发现仍会尝试运行。公开赛程和候选地址不保证覆盖所有比赛，延期、取消、特殊赛程和球队缩写仍须核对。

持续运行时，每天北京时间 15:30 后暂停采集，刷新赛程，只有确认已开赛超过 24 小时、Polymarket 事件关闭且其全部相关市场明确已结算时，才删除该比赛的赛程、市场、交易明细和检查记录，压缩数据库后继续。仅关闭交易不等于结算；状态缺失、查询失败、或本地已有市场不在返回结果中时保留数据并在 `status` 中显示原因。当前正在执行的接口请求或发现步骤结束后才会进入维护，因此可能晚于 15:30；离线错过时点后会在启动时补做。赛程刷新失败时不删除，记录错误并重试；不能匹配或没有被本次赛程确认的比赛会保留，需要人工核查。保留少量已清理地址标记，防止旧市场被重新下载。压缩后数据库大小仍取决于未到期比赛、保留的疑难记录和标记，不能保证固定上限。

注意：清理会永久删除该比赛的原始交易明细，后续不能再以这些本地数据重新计算比赛统计；如需保留长期统计，必须在清理前另行设计汇总或备份。目前没有实现自动归档或统计。

已知待验证：比赛发现是否覆盖全部 NBA 比赛、已结束比赛和新项目，接口分页在实时写入时是否会漏记录，重复成交跨查询如何区分，以及官方接口数据与网页逐项核对。缺少这些验证前不能声称记录完整。
