# Design

## Context

项目没有现有应用。公开成交接口的时间以秒表示，返回交易哈希但未证明其为成交唯一编号。

## Goals / Non-Goals

**Goals:** 可恢复采集并保存原始记录，明确覆盖限制。

**Non-Goals:** 此阶段不宣称链上逐笔唯一性、完整钱包覆盖或建立统计网站。

## Decisions

使用 SQLite 保存原始响应、查询快照和检查点。每次重叠查询按原始字段分组并保留每组出现次数的最大值，避免将同一响应中完全相同的记录合并；跨查询身份仍有歧义，标记为不确定。按时间窗口递归拆分高密度分页；单秒超过接口容量时失败而不推进检查点。比赛发现与采集分别保存状态，初次从市场创建时间开始。每次固定截止时间查询，完整保存后原子推进检查点。

通过 ESPN 公开赛程获取比赛和开赛时间，按东部时间比赛日期及客队、主队缩写生成候选 slug；从开赛前八天起查询 Gamma，只有返回匹配事件才导入。定期刷新赛程，按比赛编号更新改期；保留已发现事件继续采集。比赛不存在或接口失败分别记录，不能视为已开放。候选地址并非官方保证，继续使用 NBA 标签发现作为补充。

以北京时间每天 15:30 为维护时点，当前采集轮次结束后暂停，按可靠且最近更新的赛程开赛时间清理超过 24 小时的事件、市场、成交、检查记录及赛程，再执行 SQLite VACUUM，成功后恢复采集；无法确认或赛程未更新的比赛保留并提示。保留已清理地址的简短标记以防重新发现后重新回填。维护失败记录状态并重试，离线跨过时点则恢复后补做。数据删除不可逆。

清理前从 Gamma 重新查询事件，只有事件明确关闭、所有返回的市场明确 `umaResolutionStatus=resolved` 且关闭，并且覆盖本地已有市场时才允许删除。空市场、缺字段、查询失败或仍待结算均保留并记录核查原因；关闭本身不等于已结算。

只接受 Gamma 的 `sportsMarketType` 为 `moneyline`、`spreads`、`totals` 的市场，并保留每条盘口独立标识和原始资料；不推断未知类型。事件快照只保存上述市场。旧数据库中的其他市场不自动删除，但停止采集并在状态中提示；保留用户既有数据。结算检查仍采用此前约定的整个事件的保守条件。

## Risks / Trade-offs

- [接口数据延迟超过重叠窗口] → 周期性长窗口复查并报告不能保证完整。
- [时间相同且字段完全相同] → 保存重复次数，注明无法证明身份。
- [接口与网站口径差异] → 保存来源与原始数据，不声称与网站一致。
